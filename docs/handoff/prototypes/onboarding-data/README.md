# Onboarding prototype: bring your data in (2026-10-09)

Reference only, never shipped (like the other prototypes). Plan: [../../../ONBOARDING_REDESIGN.md](../../../ONBOARDING_REDESIGN.md).

These are the artboards of a claude.ai Design canvas (`canvas.json` is its index; the files are `.dc.html` boards). They need that canvas to open: they are not standalone pages. They use the admin prototype's top bar and rail ([../admin-v2/](../admin-v2/)), the logo palette, and Niva as the assistant.

| File | Board |
|---|---|
| `Main.dc.html` | 1 One front door: plan, drop zone with recognition, connectors, templates, helpers, what Niva sees |
| `Templates.dc.html` | 2a Starter workbook, tabs in load order, column guide, a plain-words check |
| `Connect.dc.html` | 2b QuickBooks, Neon, Zeffy and Google Sheets: what comes in, pull once or keep in step, test, a failed attempt |
| `Files.dc.html` | 2c A spreadsheet read by Niva (recipe, column matching, two questions) and a photo read on Weaver's servers |
| `Review.dc.html` | 3 Totals to the cent, household cards with evidence, auto-linked list, confirm and undo |
| `Ready.dc.html` | 4 Data completeness, asking the families, parallel run and cutover, slow steps, helpers |
| `Rail.dc.html`, `TopBar.dc.html` | Shared parts, copied from the admin prototype with the community name changed |

All people, households, amounts and counts are made-up sample data. Nothing about children is shown to Niva in the design (decision D2 in [ADMIN_REDESIGN.md](../../../ADMIN_REDESIGN.md)).
